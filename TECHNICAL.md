# ESPORTS LAB — CS2 и Dota 2

Первая версия личного Telegram-бота для анализа матчей и проверки гипотез на виртуальном банке. Python 3.11+, без сторонних Python-пакетов. Тексты и время — по-русски, часовой пояс Europe/Moscow.

**Статус v0.3:** локальный прототип с необязательным импортом линии BetBoom через API-SPORT и режимом настройки с iPhone. Офлайн-демо и 37 автоматических проверок выполнены; подключение к настоящим Telegram/PandaScore/API-SPORT не проверялось, потому что личные API-токены не предоставлены. Бот не создан в аккаунте Telegram и не размещён на сервере. Прогнозная точность и прибыльность не подтверждены.

Для облачного запуска без компьютера подготовлен отдельный пакет `esports-iphone.zip` с `app.zip`, `render.yaml` и `IPHONE_SETUP.md`. Развёртывание требует аккаунтов GitHub/Render и проверки стоимости перед запуском платного worker/диска. Они не созданы и не оплачены автоматически. В Render ключи задаются в Environment, владелец привязывается командой `/pair КОД` со случайным `PAIRING_CODE` от 24 символов. Числовой ID для этого варианта знать не нужно.

## Что уже умеет

- Получает предстоящие матчи и результаты CS2/Dota 2 через документированный API PandaScore, обновляет их каждые 15 минут при работе процесса.
- Использует простой Elo по результатам **серий**, отдельно для каждой игры и формата BO1/BO3/BO5. Не выдаёт его за модель драфта, карт, составов или инсайдерских новостей.
- Отказывается от расчёта при нехватке истории команды, устаревшем источнике, неизвестном формате, BO2, техническом результате, ничьей или уже начавшемся матче.
- Принимает вручную коэффициенты обоих исходов победителя серии; показывает маржу, нормированные веса рынка, порог безубыточности и условный EV.
- Может импортировать коэффициенты BetBoom через документированный сторонний API-SPORT. Это отдельный провайдер данных, а не официальный API BetBoom. Импорт выключен по умолчанию.
- Хранит отдельно справочный реальный баланс и виртуальный банк. Реального доступа к букмекерскому аккаунту нет.
- Ведёт виртуальный журнал, автоматически рассчитывает результаты после обновления источника, считает P&L, ROI, открытую сумму под риском и просадку по закрытым результатам.
- Формирует сводку по команде или ежедневно в указанное время Москвы. Может честно сообщить, что подходящих событий нет.
- Считает условный экспресс из двух событий. Не объединяет один матч, общую команду или турнир; остальные зависимости всё равно могут сохраняться.
- Отвечает только владельцу в личном чате. Токены не печатаются в штатных сообщениях и логах. База и экспорт создаются с правами 0600.

## Что означает «рекомендация» в этой версии

**Реальные деньги: 0%.** Модель экспериментальная, не откалибрована и не доказала преимущество над линией БК. Положительный EV, вычисленный из неточной вероятности, может оказаться отрицательным в действительности.

Для сравнения гипотез используется виртуальная сделка в **0.25%** виртуального банка: максимум **1%** в открытых сделках и **1%** суммарно размещённых за скользящие 24 часа. Это фиксированные параметры эксперимента, а не безопасная стратегия реальных ставок. Сумма округляется вниз до сотых. Если лимит исчерпан, новой записи нет. Сумма не увеличивается после проигрыша.

Реальный баланс задаётся вручную и служит только справкой. Результаты виртуальных сделок не меняют его. Все деньги в журнале — условные единицы. Сброс виртуального банка через чат не предусмотрен, чтобы не стирать убыточную историю.

При экспрессе произведение вероятностей допустимо только при независимости. Бот явно показывает это допущение. Даже без общей команды независимость не доказана. Два события с вероятностями 70% каждое при независимости дают 49% на оба исхода и 51% на проигрыш экспресса. Эти цифры — математический пример, не оценка настоящих матчей.

## Быстрый офлайн-просмотр

Распакуй архив, открой терминал в папке `esports-lab` и выполни:

```bash
python3 -m esports_bot demo
```

Демо не требует ключей и сети, не пишет в рабочую базу. Все имена команд, матчи, коэффициенты и результаты в нём вымышленные. Готовый текст демо также есть в `DEMO_PREVIEW.txt`.

Проверки:

```bash
python3 -m unittest discover -s tests -v
```

## Запуск в Telegram

1. Создай своего бота через официальный [@BotFather](https://t.me/BotFather) и получи `TELEGRAM_BOT_TOKEN`.
2. Узнай числовой ID своего Telegram-аккаунта. Это `OWNER_TELEGRAM_ID`, не username и не номер телефона. Если не знаешь ID, можно сначала написать новому боту и посмотреть поле `message.from.id` через официальный метод `getUpdates` в своём локальном окружении. Не публикуй URL с токеном.
3. Получи токен в аккаунте [PandaScore](https://app.pandascore.co/). Подтверди доступ к расписанию и результатам обеих игр. Подробная игровая статистика может требовать другой план.
4. Скопируй `.env.example` в `.env` и заполни три значения. Храни токены локально; не отправляй их в чат. На Linux/macOS установи `chmod 600 .env`.
5. Проверь наличие настроек, загрузи историю и запусти процесс:

```bash
python3 -m esports_bot doctor
python3 -m esports_bot sync --pages 20
python3 -m esports_bot run
```

`doctor` проверяет наличие настроек, а не валидность ключей в сети. Первая загрузка берёт до 2000 результатов на игру; это ограниченная выборка, а не вся история киберспорта. Если источник не отдаёт столько данных, бот использует доступные. Максимум 100 страниц задаётся явно; это увеличивает число запросов. В рабочем цикле обновляются последние 2 страницы результатов, до 3 страниц расписания, последние изменённые записи и матчи с открытыми виртуальными сделками.

В v0.3 можно сначала запустить только Telegram с токеном и безопасной привязкой владельца, затем подключить источники. Без `PANDASCORE_TOKEN` живые матчи не загружаются; `/status` объясняет, чего не хватает. Если владелец не задан через `OWNER_TELEGRAM_ID` и ещё не сохранён в базе, требуется секрет `PAIRING_CODE`. Первый случайный посетитель без этого кода владельцем не становится. После сохранения владельца повторная привязка отключена. Пять неверных кодов блокируют привязку для этого отправителя на сутки.

Первая попытка обновления истории при работе `run` теперь также запрашивает до 20 страниц, следующие — 2. Отметка попытки сохраняется, чтобы неверный ключ при постоянных перезапусках не запускал полный импорт заново. Явная команда `sync --pages 20` остаётся доступной для повторной загрузки.

Пока процесс работает, он получает сообщения, обновляет данные и отправляет включённую сводку. Остановка компьютера останавливает бота. Для непрерывной работы нужен отдельный постоянно работающий хост; он в этом пакете не настроен. На Windows используется `python` вместо `python3`; если системная база часовых поясов отсутствует, установи `tzdata`.

Один токен — один polling-процесс. Если у бота уже есть webhook, программа завершится с объяснением: она не удаляет чужую настройку автоматически.

## Подключение коэффициентов BetBoom

В [документации API-SPORT](https://docs.api-sport.ru/concepts/bookmaker-odds) заявлены коэффициенты BetBoom для киберспорта. Наличие нужной линии, доступ по тарифу и соответствие твоей версии сайта BetBoom **не проверены на живых ответах**. До оплаты провайдера проверь это на доступном тестовом доступе и сравни один и тот же рынок с приложением БК.

Потребуется отдельный `API_SPORT_KEY` из аккаунта провайдера; это не логин или пароль BetBoom. Сначала заполни ключ в `.env`, оставляя `BETBOOM_AUTO=0`, и выполни одну загрузку после получения расписания PandaScore:

```bash
python3 -m esports_bot betboom-sync
python3 -m esports_bot report
```

Отчёт показывает число полученных, импортированных и пропущенных событий. Ноль импортов не означает отсутствия матчей: причины могут быть в покрытии, разных названиях, неизвестной категории, формате или снятой линии. Настоящие ответы этой интеграцией здесь не проверены.

Если разовая проверка подтвердила нужное покрытие и квоту, для фонового импорта установи `BETBOOM_AUTO=1` и перезапусти `run`. Интервал `BETBOOM_POLL_SECONDS` по умолчанию 300 секунд; один цикл делает от 1 до 3 запросов. Непрерывный опрос раз в 5 минут расходует минимум 288 запросов в сутки. Не включай его при недостаточной квоте. Этот пакет не оформляет подписку и ничего не оплачивает.

Сопоставление событий строгое: совпадающая дисциплина, формат BO, точные названия команд после нормализации регистра/пробелов и время с расхождением максимум 5 минут. Неизвестные категории и неоднозначные пары пропускаются. Academy, женские составы, переводы и похожие названия не объединяются автоматически. Порядок команд у двух источников может отличаться: коэффициенты тогда переставляются по командам. При изменении порядка или времени в расписании старый снимок блокируется.

Импортируется только активный двухисходный прематч-рынок `result` BetBoom. Live, ничья, карты, форы и тоталы исключены. Возраст считается по времени **прематч-доски у источника**, а не по моменту скачивания; предел — 10 минут. Снятые рынки и ошибка обновления удаляют прежние автоматически импортированные цены, сохраняя снимки в виртуальном журнале. Ручные коэффициенты остаются отдельными записями и тоже имеют срок годности.

Текущая котировка в приложении БК может уже отличаться. Импорт не означает, что по цене можно заключить реальное пари. Баланс BetBoom по-прежнему вводится вручную, автоматические реальные ставки отсутствуют. Ограничение реальной рекомендации в 0% сохраняется.

## Команды

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Справка |
| `/matches` | Ближайшие матчи на 48 часов, до 20 в одном ответе |
| `/analyze csgo:123` | Оценка серии, ограничения, состояние данных |
| `/odds csgo:123 1.80 2.05 НазваниеБК` | Коэффициенты A и B по порядку из `/analyze`; годны 10 минут |
| `/betboom` | Состояние последней загрузки линии через API-SPORT |
| `/status` | Состояние подключения источников и привязки |
| `/balance 10000` | Справочный реальный баланс без доступа к БК |
| `/paperbank 10000` | Однократно создать виртуальный банк |
| `/paper csgo:123 A` | Виртуальная сделка только при разрешении текущего эксперимента |
| `/bank`, `/stats` | Виртуальные итоги и справочный реальный баланс |
| `/journal` | Последние 10 виртуальных записей |
| `/today` | Сводка по текущему кэшу и условный сценарий экспресса, если он есть |
| `/express` | Подобрать два доступных виртуальных кандидата для расчёта |
| `/express csgo:123:A dota2:456:B` | Рассчитать конкретную пару исходов |
| `/model` | Проверка Elo на загруженной истории |
| `/subscribe 10:00` | Сводка в 10:00 Москвы, только пока бот запущен |
| `/unsubscribe` | Отключить сводку |

ID в таблице — примеры синтаксиса. Настоящие идентификаторы нужно брать из `/matches`. CS2 использует префикс `csgo` из API PandaScore. Коэффициенты вводятся для **победителя всей серии с двумя исходами**. Форы, карты, тоталы, ничьи, ставки с особыми правилами и live здесь не поддерживаются.

Без свежих коэффициентов автоматическая сводка всё равно приходит, но новых виртуальных кандидатов не предлагает. Для BetBoom подготовлен необязательный автоматический импорт через API-SPORT, описанный выше. Подмены недостающих цен котировками другого букмекера или общими `oddsBase` нет.

## Как устроена проверка модели

Для каждого исторического начала матча Elo обучается только на результатах, **завершённых до этого начала**, включая случай параллельных матчей. Прогрев: минимум 10 завершённых серий того же BO на каждую команду, плюс недавний результат не старше 45 дней. Эти пороги — фильтры пригодности, не доказательство надёжности.

Выводятся число прогнозов, Brier score, log loss и доля угаданных по каждой игре/BO. JSON-отчёт дополнительно включает таблицу калибровки. Ориентир 50/50: Brier 0.25 и log loss 0.6931. Его преодоление не доказывает преимущество над рыночной моделью.

Исторических коэффициентов в пакете нет, поэтому исторический ROI не рассчитывается. ROI виртуального журнала использует только реально записанные до матча котировки. Открытые ставки не оцениваются по рынку; просадка считается по закрытым результатам и не отражает всю возможную будущую потерю.

Ограничения: история может быть неполной и исправленной задним числом; нет сохранённых point-in-time составов, замены игроков, патча, veto, карт и драфтов. Никакой автоматической «сертификации» модели по числу матчей нет. Перед выводами о реальных деньгах нужны независимая хронологическая проверка, калибровка на отдельной выборке, сравнение с рыночной линией и длительное наблюдение новых прогнозов с заранее зафиксированными правилами.

## Правила виртуального расчёта

Обычный завершённый матч оплачивается по победителю и коэффициенту, сохранённым при записи. Порядок A/B после записи может поменяться у источника: расчёт всё равно использует исходный ID команды. Повторный расчёт не дублирует выплату.

Отмена, технический результат, ничья или неподдерживаемый завершённый формат возвращают виртуальную сумму. Это правило **этого эксперимента**, не воспроизведение регламента конкретной БК. Задержанный или неизвестный результат остаётся открытым. Исправления источника после окончательного расчёта автоматически не переписывают журнал и требуют отдельной сверки.

Перед записью проверяются свежесть данных, свежесть коэффициентов и неизменность времени/сторон после ввода линии. Сводки и команды обрабатываются с сохранением намерения до ответа: при аварии одна сводка или ответ может не дойти, зато повторная доставка не должна повторить денежную запись. Повторно отправить сводку можно через `/today`.

## Экспорт и файлы

```bash
python3 -m esports_bot report > research-report.json
python3 -m esports_bot export --out virtual-journal.json
```

`report` читает текущий кэш, не запрашивая новую линию. `export` создаёт новый файл и не перезаписывает существующий. SQLite-база находится в `data/research.sqlite3`, путь меняется через `BOT_DB` или глобальный аргумент `--db`. Береги резервную копию базы: она хранит виртуальную историю. В экспорт входят снимки матчей и коэффициентов, но API-токены туда не включаются.

Файлы проекта: `core.py` — математика и модель; `providers.py` — PandaScore/Telegram; `betboom.py` — необязательный импорт BetBoom через API-SPORT; `store.py` — кэш и журнал; `service.py` — команды; `__main__.py` — запуск и расписание; `tests/` — проверки. При обновлении с v0.1 база расширяется автоматически, история сделок сохраняется.
