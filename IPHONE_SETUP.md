# Настройка @BETONFIRES_BOT с iPhone

Исходники уже находятся в `cloudise/betonfires-bot`. Загружать архивы и пользоваться командной строкой на iPhone не требуется. Подготовка кода завершена; настоящий запуск, оплата хостинга и подключение ключей ещё не выполнены.

## 1. Проверить стоимость размещения

Открой [настройку Render для этого репозитория](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fcloudise%2Fbetonfires-bot) в Safari и войди в свой аккаунт Render.

В шаблоне указан **платный** worker `0.5c-512mb`, один экземпляр и постоянный диск 1 GB. Не подтверждай создание ресурсов, пока итоговая стоимость, валюта, налоги и условия оплаты на экране Render не подходят. Код сам не регистрирует аккаунт, не подключает карту и не оплачивает ресурсы. Цена источника коэффициентов не входит в стоимость worker.

Если экран показывает выбор репозитория, укажи `cloudise/betonfires-bot`; путь Blueprint — `render.yaml`. Если нужно, используй в Safari «Запросить настольный веб-сайт». Живой запуск через мобильный интерфейс здесь не проверялся.

Документация: [тарифы](https://render.com/pricing), [Blueprint](https://render.com/docs/blueprint-spec), [worker](https://render.com/docs/background-workers).

## 2. Ввести токен Telegram

Render запросит `TELEGRAM_BOT_TOKEN`. Это значение из официального [@BotFather](https://t.me/BotFather) для твоего бота. Вводи его только в поле настроек хостинга. В исходники GitHub токен не добавляется.

После проверки стоимости и подтверждения развёртывания Render выполнит 37 тестов, затем запустит программу. Должен работать ровно один экземпляр; второй polling-процесс с тем же токеном Telegram приведёт к конфликту.

## 3. Привязать владельца

В worker открой **Environment**, найди автоматически созданный `PAIRING_CODE`, открой значение и скопируй. В личном чате с [@BETONFIRES_BOT](https://t.me/BETONFIRES_BOT) отправь:

```
/pair КОД
```

Замени `КОД` скопированным значением. Бот сохранит твой Telegram ID и подтвердит привязку. Первый случайный пользователь без кода владельцем не становится; код не выводится в лог и не сохраняется в базе. Пять неверных попыток блокируют привязку для отправителя на сутки.

Отправь `/status`, затем `/help`. После успешной привязки можно удалить `PAIRING_CODE` из Environment и перезапустить worker: владелец уже записан на постоянном диске. Повторная привязка через старый код отключена.

## 4. Подключить реальные матчи

Получи ключ в аккаунте [PandaScore](https://app.pandascore.co/) и проверь доступ к расписанию и результатам CS2/Dota 2. В Environment worker добавь `PANDASCORE_TOKEN` и сохрани с перезапуском.

При первой попытке программа загружает до 2000 результатов на игру. Затем обновляет результаты и расписание каждые 15 минут. Нехватка подходящей истории приводит к пропуску матча; бот не заменяет данные вымышленными.

Проверь `/matches`, `/analyze ID`, `/model`. Подробная статистика составов, veto, карт, патча и драфта в текущую Elo-модель не входит. Ключ провайдера не является доказательством точности модели.

## 5. Проверить линию BetBoom

Подготовлен импорт через **сторонний API-SPORT**, а не официальный API BetBoom. Его настоящие ответы ещё не проверены. До оплаты провайдера проверь тестовое покрытие именно BetBoom, CS2 и Dota 2 и сравни одинаковые матчи/рынки с приложением БК.

В Environment добавляются `API_SPORT_KEY` и, после проверки покрытия и квоты, `BETBOOM_AUTO=1`. Интервал `BETBOOM_POLL_SECONDS=300` делает от одного до трёх запросов каждые пять минут — минимум 288 запросов в сутки. Не включай его при недостаточной квоте. После изменения переменных перезапусти worker.

Проверка: `/betboom`, затем `/analyze ID`. Стороны команд, время матча и рынок должны совпадать. Используется только двухисходный прематч-рынок победителя серии; live, ничья, снятые рынки, старые цены и неоднозначные пары не подходят. Возраст цены определяется по времени доски у источника, а не по моменту скачивания. Цена в приложении БК может измениться раньше обновления провайдера.

Ручной ввод остаётся доступным:

```
/odds ID КФ_A КФ_B BetBoom
```

Коэффициенты действуют 10 минут. Реальный баланс вводится вручную через `/balance`, виртуальный банк создаётся однократно через `/paperbank`. Автоматических реальных ставок нет; реальная рекомендация остаётся 0%.

## 6. Ежедневное использование

- `/subscribe 10:00` включает сводку на 10:00 Москвы, пока работает worker.
- Открытый Safari не нужен. Все команды отправляются в личный чат боту.
- База хранится по пути `/var/data/research.sqlite3` на постоянном диске. Смена или удаление диска может уничтожить владельца и журнал; диск не заменяет резервную копию.
- Репозиторий сам не хранит токены. Они задаются в Environment хостинга.
- Авторазвёртывание кода выключено. После изменения исходников нужен осознанный запуск новой версии.
- Остановка worker прекращает ответы. Условия начисления платы за остановленные ресурсы и оставшийся диск уточни в Render; остановка процесса не обязательно удаляет платное хранилище.

Модель пока экспериментальная. Виртуальные результаты и количество прошедших тестов не обещают прибыли на настоящих деньгах.
